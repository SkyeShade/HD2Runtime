# PelicanGatlingProof 0.2.0 (development only, solo host): the Gatling's package loaded, the chin turret's removal

**0.1.0 live:**
- **REPLACE** spawned and attached a Gatling that followed the Pelican, ran its AI and fired 148 at 1600 RPM with its
  pattern and spin-up. The game removed it with the Pelican.
- **Three problems:**
  - the chin turret stayed, so the Pelican carried two turrets;
  - the Gatling showed its whole sentry, ground base included;
  - it spawned only with the Gatling Sentry in the loadout.
- **WEAPON:** the chin turret fired 148 at 1600 RPM continuously.

**0.2.0:**
- **No loadout needed.** In a mission (mode REPLACE) the Gatling Sentry's package is requested through the Runtime's
  asset loader. Expect `assets for pelican-gatling requested: 1 package(s)`, then `assets for pelican-gatling resident`.
  REPLACE waits for it and is refused (ASSET_UNAVAILABLE) if it does not load within 90 s.
- **Why the chin turret stays.** `PELICAN GATLING REMOVAL` lines before and after the game's removal call show the
  turret's network id, its network flag (set means the game only sends a removal request) and the pending removals.
- **Second removal attempt.** If the chin turret is still alive 2 s later, the game's own destroy routine is called
  for it, not forced (the game's own ownership check stays). `PELICAN GATLING DESTROY` and `GATLING REMOVAL` lines
  give the result.
- **The ground base.**
  - `GATLING UNIT API` lists which engine unit functions exist.
  - `GATLING UNIT` finds the Gatling's own unit and its mesh count.
  - **Ctrl+Shift+F3** hides the next mesh of the newest Gatling (1, 2, 3, ...). This is render state of that one
    unit; it goes with the unit. Press it slowly and note which numbers remove the ground base.

The first line is `PelicanGatlingProof 0.2.0 GATLING PACKAGE-LOADER BUILD (solo host; no Gatling Sentry needed in the
loadout)`.

**Live test:**
- **Setup:** solo host, **without** the Gatling Sentry in your loadout. Install this hand-off's runtime ZIP,
  `PelicanGatlingProof-0.2.0.zip` and `PelicanCasProof-0.1.1.zip`.
- **Steps:**
  1. In a mission, check for the two `assets for pelican-gatling` lines.
  2. Call Pelican CAS near enemies.
  3. After `GATLING UNIT`, press Ctrl+Shift+F3 once every few seconds while watching the Gatling. Note which presses

  each Ctrl+Shift+F3 press hid.

# PelicanGatlingProof 0.1.0 (development only, solo host): one Pelican's chin turret as a Gatling turret

A capability proof, not part of the custom-stratagem builder. It changes **one Runtime-spawned Pelican's own chin
turret** (`shuttle_gunship_turret_hmg`) into a Gatling turret, using the game's own routines. No shared definition is
written. Research: research/docs/pelican-cas-F5FEE03DCFDB.md, section 16.

## What it does

Install it with PelicanCasProof. Each Pelican CAS Pelican is changed **once**, 3 s after it starts hovering, in the
current mode.

**REPLACE (the default)** puts a real Gatling Sentry turret entity where the chin turret was, through the game's own
calls:
1. The spawn request creates one `gatling_turret`, with no spawn context.
2. The attach routine (the one the mount system uses for every mounted child) attaches it to the Pelican's unit at the
   chin turret's node (41), with the chin turret's own local offset and rotation.
3. One guarded write puts the Gatling in the chin turret's slot of the **Pelican's own** mount record. The game's
   teardown then removes the Gatling with the Pelican.
4. The chin turret is unlinked and removed, the same way the teardown does it.

The Gatling keeps its own AI (behaviour 213), weapon (projectile 148, 1600 RPM), ammo pattern (148, 148, 148, 242,
148) and spin-up (wind-up) component.

**WEAPON (the fallback)** keeps the chin turret entity:
1. The game's copy routine gives this one turret its own ProjectileWeapon record (an unmodified copy of its type's).
2. One guarded transaction sets that copy's projectile to 148 and the turret's own current RPM to 1600. The engine
   derives the shot interval from the RPM.

The ammo pattern stays off (it is type data) and there is no spin-up (it is a separate component).

**Refused, with nothing called or written,** unless:
- the build pins and each routine's exact entry bytes prove;
- it runs inside the Runtime's update;
- you are in a mission as the solo host;
- the Pelican was spawned by the Runtime and is hovering;
- exactly one chin turret is attached to it, and the Pelican's mount record names that turret.

REPLACE also needs the Gatling Sentry's package loaded, so bring the A/G-16 Gatling Sentry in your loadout.

If the attach does not take, the Gatling is removed again and the chin turret is left as it was.

## Which build is running

The first line is `PelicanGatlingProof 0.1.0 GATLING TURRET BUILD (solo host)`.
- Ctrl+Shift+F6 switches the mode for Pelicans seen from then on: REPLACE -> WEAPON -> OFF.
- Ctrl+Shift+F4 prints the status.

## Live test

**Setup:** solo, as host, with the A/G-16 Gatling Sentry in your loadout. Install this hand-off's HD2Runtime runtime
ZIP, `PelicanGatlingProof-0.1.0.zip` and `PelicanCasProof-0.1.1.zip`. PelicanTurretProbe 0.3.0 is optional; it adds
`TURRET` lines.

1. **REPLACE.** In a mission with enemies, call Pelican CAS near enemies. Wait for the hover. Expect, in order:
   - `PELICAN GATLING BEFORE`, `ATTEMPT`, `SPAWNED`, `ATTACHED` and `APPLIED` (or `REFUSED` with a reason);
   - `GATLING VERIFY` after 5 s and again after 30 s;
   - `GATLING SAMPLE` every 2 s, and `GATLING FIRE` while it shoots.

   Watch the Pelican's chin for the whole hover.
2. When the Pelican leaves, expect `GATLING TEARDOWN`: removed with its Pelican, or a Runtime cleanup.
3. **WEAPON.** Press Ctrl+Shift+F6 once (mode WEAPON). Call Pelican CAS again and expect the same kinds of lines.

**Send:**
- every line starting with `PelicanGatlingProof`, `PELICAN GATLING`, `GATLING` and `Ctrl+Shift+F`;
- for each mode: what the chin looked like, whether the turret moved with the Pelican, whether it fired and at what,
  how fast it fired, and whether it spun up first;
- anything odd: a falling or floating turret, a crash, the Pelican misbehaving.
