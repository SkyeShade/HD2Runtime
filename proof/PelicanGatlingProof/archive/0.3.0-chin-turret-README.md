# PelicanGatlingProof 0.3.0 (development only, solo host): the Pelican's own chin turret as a Gatling Sentry

The chin turret keeps its entity, model, mount, node 41, parent link and movement. For that one Pelican it gets the
Gatling Sentry's projectile, rate, casing, AI and 10x its ammunition. Nothing shared is written: every Pelican, Gatling,
weapon, magazine and projectile definition is read, never changed, and the proof compares them whole before and after.
Research: docs/research/pelican-cas-F5FEE03DCFDB.md, section 19.

The 0.2.0 physical Gatling replacement is set aside. It stays a separate experimental capability (runtime
`pelican_gatling.replace`; the 0.2.0 proof source is kept in `archive/`).

## What it does

As soon as a Runtime Pelican's chin turret exists and is uniquely identified (during its approach):

1. **GATLING CONFIG.** The Gatling Sentry is read from the game, read-only: its type records (projectile, rate, casing,
   magazine), and a deployed Gatling Sentry's own records when one exists. The turret's own ProjectileWeapon copy then
   gets, in one guarded transaction:
   - projectile 148;
   - the Gatling Sentry's exact rate: its type's RPM times the factor the game applied to this turret (1, or 0.9 under
     the mission fire-rate modifier); a deployed Gatling Sentry's own rate must agree;
   - the rate slot, so the game re-derives the same rate if it ever does.
2. **GATLING CASING.** In the same transaction, before the turret's first shot, its copy's casing (particles and
   parameters) becomes the Gatling's. On its first shot the game looks up the Gatling's pooled casing effect and keeps it
   for that turret. If the turret has already fired, the casing is not applied and the log says why.
3. **GATLING AMMO.** The turret's own magazine copy gets 10x the Gatling Sentry's magazine capacity, read from the game,
   and the magazine is filled.
4. **GATLING AI.** The game's SetBehaviour with the Gatling Sentry's AI (213) while the turret is quiet, read back
   (`behaviour BEFORE = 645`, `behaviour AFTER = 213`), as in PelicanGatlingAIProof 0.2.0.
5. **GATLING TARGET.** Every target change. The Gatling AI leaves its firing stage only when it is empty or its target
   has been lost for 1 s, and any brief re-pick resets that; it never checks where the barrel points. So, while it
   fires, if for 2 s it has no valid target, or its target takes no damage (the chin turret cannot reach it), the
   proof queues the AI's own transition out of firing, the one the game itself uses (`NO-TARGET RELEASE`, then `... ran`).
   The AI then fires again only with the barrel within 3 degrees of a target, or goes back to searching. A different
   target, or any hit, gets a fresh 2 s, so A lost -> B acquired keeps it firing.
6. **GATLING FIRE.** Rounds every 2 s, and the round chambered at configuration (fired first; see below).
7. **GATLING ORBIT.** The live-proven orbit (OrbitProof 0.2.0's): a 15 s spiral climb, then 40 m around the beacon,
   60 m above it, for 55 s inside the CAS proof's 60 s hold. No attempt to turn the nose.
8. **GATLING SUMMARY** when the Pelican leaves.

**The first shot.** The round already chambered when the weapon is copied is an autocannon round (120). The game fires
it first and chambers every later round from the copy (148). This is recorded, not changed.

**Expected side effect.** PelicanCasProof's own summary reads `CHECK` instead of `PASS: it held over the beacon`
because the orbit takes the Pelican 40 m out. The CAS proof itself is unchanged.

**Keys** (each applies to Pelicans seen from then on):
- Ctrl+Shift+F2: rate (the Gatling Sentry's -> 600 -> 1000).
- Ctrl+F9: AI 213 on/off.
- Ctrl+F10: the Gatling ammo pattern on/off (off by default).
- Ctrl+F11: orbit on/off.
- Ctrl+Shift+F1: status.

## Live test

**Setup:** solo host. Install this hand-off's runtime ZIP, `PelicanGatlingProof-0.3.0.zip` and
`PelicanCasProof-0.1.1.zip`. Do not install PelicanGatlingAIProof or any other Pelican proof alongside it.

1. Call Pelican CAS near a group of enemies. During the approach expect, in order: `GATLING CONFIG ... REFERENCE`,
   `GATLING CASING ... BEFORE`, `GATLING CONFIG ... APPLIED`, `GATLING CASING ... AFTER`, `GATLING AMMO`,
   `GATLING AI ... RESULT ... behaviour AFTER = 213`.
2. Once it hovers: `GATLING ORBIT ... STARTED`, the spiral climb, `ESTABLISHED`.
3. Watch the chin gun and note:
   - the ejected casings: small Gatling casings, not the large autocannon shells;
   - the projectile after the first shot;
   - target A acquired -> continuous fire -> A lost -> a new target quickly -> fire continues;
   - target lost with no replacement -> firing stops within about 2 s (`NO-TARGET RELEASE`) and it searches again;
   - a target it cannot aim at: it eventually stops firing rather than shooting into the ground.
4. After it leaves: `GATLING SUMMARY`.

**Send** every line starting with `PelicanGatlingProof`, `PELICAN WEAPON`, `GATLING ` and `assets for`, and what the chin
gun did at each step.
