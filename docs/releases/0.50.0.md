# HD2Runtime 0.50.0 — the HellForge bridge

Released 2026-10-21 to HellForge's beta testers. 0.50.0 runs on HellForge (0.1.8 BETA and newer) as a bridge: there
it changes nothing in the game itself, and HellForge makes every change. Outside HellForge it is 0.40.1 unchanged.

Each item says whether it was seen working in game ("live") or is covered only by the offline tests.

## On HellForge (offline tests only)

`docs/hellforge.md` has the whole picture. In short:

- **Writes.** `hd2.patch`, `transaction`, `plan` and `ensure` validate as before, then become HellForge live edits of
  the same fields: every field the catalogues let mods write has a route (component records, settings rows, stratagem
  definitions and codes, boosters, attachments, mission timers, status multipliers, armor perks, the G-109 Urchin's
  pulse). HellForge's F8 editor shows each value with the mod that set it (`lua.<mod>`, purple) and resets to it.
- **Events.** Every event comes from HellForge: its game state, players, spawns, kills, damage, heals, mission stats,
  weapons, explosions (every request, none missed) and bug holes.
- **Actions.** heal, limbs, injure, statuses, velocity, the Supply Pack, explosions, projectiles, homing, per-shot
  changes, the Pelican, kill credit and the mission timer freeze keep their checks and answers; HellForge's engine
  makes the game call. `modify_shots`'s `on_shot` callbacks are not called there.
- **Unavailable on HellForge:** custom stratagems (for good: they are HellForge stratagem mods) and enemy controls
  (until HellForge maps enemies). Their calls answer `HELLFORGE_UNAVAILABLE` and the mod keeps running.
- **Safety.** In a HellForge session whose bridge cannot be used (an older HellForge), writes are refused, never made
  by the Runtime itself. The release's `hd2runtime.json` names the bridge it is made for (`"hellforge": {"bridge": 3}`).

Mods made for HD2Runtime need no change. `requires.hd2runtime.min_version` stays whatever they need: 0.50.0 adds no
API of its own.
