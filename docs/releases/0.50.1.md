# HD2Runtime 0.50.1 — HellForge: no more periodic stalls from ensures

Released 2026-10-24. A fix for 0.50.0 on HellForge (0.1.8 BETA and newer, 0.2.0 included: it uses the same Lua bridge,
3). Outside HellForge nothing changed: it is 0.40.1 there.

## On HellForge (offline tests; the stall was seen live)

- **Ensures apply once and are then held by HellForge.** On 0.50.0 a patch, transaction or plan applied through
  HellForge had no byte check, so every `hd2.ensure` ran a full pass on every interval and never backed off. With many
  ensures (Total Arsenal Overhaul registers about 500) they all re-sent every field in the same frame: the game froze
  for about half a second every few minutes (HellForge bug-report-0043). Fields one ensure sets and another puts back
  also went back and forth on each pass. HellForge keeps a Lua mod's live edits for the whole session, its data reloads
  included, so an ensure's check now holds while the bridge does: it backs off as a byte-checked one does, and the log
  says `steady=held by HellForge`. An ensure still applies anew when one of its options changes.

Mods need no change, and `requires.hd2runtime.min_version` stays whatever they need: 0.50.1 adds no API.
