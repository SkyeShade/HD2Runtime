# HD2Runtime 0.23.1

HD2Runtime 0.23.1 adds guarded authoring for magazine attachments, the attachment-owned ammo values
on weapons with selectable magazines. See [magazine attachments](../magazine-attachments.md).

- **Where the ammo values live.** On these weapons the round count belongs to the magazine attachment
  definition, not the weapon record. Each attachment's entity delta, keyed by its AddPath, patches
  `WeaponMagazineComponentData`: capacity, starting magazines, magazines from supply, and spare
  magazines. On 14 attachment weapons the weapon record's own capacity is a placeholder (30), while
  the default magazine's delta equals the published in-game value (Concussive 60, Breaker 16, ...).
  `weapon.capacity` stays read-only on those weapons.
- **API.** `hd2.weapon_attachment(...)`, `weapon:magazine_attachments()`, and
  `weapon:magazine_attachment(name)` cover 43 native magazine attachments with 172 fields, and each
  attachment has a stable semantic ID. The catalog is `sdk/MagazineAttachmentCapabilities.json`.
- **Required acknowledgements.** Writes re-prove the full delta chain in the live read-only delta
  allocation. They require `allow_shared` (every weapon that equips the attachment is affected) and
  `allow_unverified_effect` (re-application at weapon construction is not yet gameplay-tested).
- **Weapon mapping.** Weapon options map to native attachments by native default, or by a unique
  exact published-effect fingerprint. Ambiguous options list their candidates instead of being
  guessed. Magazine selection remains read-only.
- **Validation.** All 172 fields validate against the retained snapshot. The
  `ConcussiveDrumMagazine` example (60 to 90 rounds) matches its expected native write exactly and
  applies end to end in the steady-state audit.

Runtime changes:

- The entity delta table is located as its own uniquely owned allocation.
- The guarded transaction core accepts explicitly declared byte-packed (unaligned, page-contained)
  4-byte writes; 52 attachment fields need this.
