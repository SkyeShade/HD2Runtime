# HD2Runtime 0.26.0

HD2Runtime 0.26.0 adds seven authoring areas:

- every magazine option, not only the default;
- third-person reticles;
- native fire-mode sets;
- mounted weapons on vehicles and Exosuits;
- stratagem mission-use counts, including real unlimited;
- backpack-fed support-weapon ammunition;
- drop-pod payload slots.

All of it goes through the same guarded patch, transaction, plan and ensure paths as before. Existing
fields, guards and baselines are unchanged, and no 0.25.1 behavior changes.

The release contains five feature commits since 0.25.1:

| Commit | Scope |
| --- | --- |
| `c36ae30` | Magazine options, third-person reticles, attachment metadata |
| `4121a61` | Native fire modes |
| `c143fbc` | Vehicle mounted weapons, stratagem mission uses |
| `6208aa2` | Backpack-fed support-weapon ammunition |
| `e04c79f` | Drop-pod payload slots and spawn counts |

## Evidence levels

Every new field publishes how well it is proven. Only a small part of this release is gameplay-proven;
**most new fields have not been tested in game.**

| Level | Meaning | Acknowledgement |
| --- | --- | --- |
| **Gameplay-proven** | A working reference mod or a user-confirmed live test made this exact change on this exact record | None beyond scope |
| **Structurally / natively proven** | Ownership, offset and storage are proven against the pinned type library and live snapshot, and values match scraped fingerprints; the in-game effect of an edit is untested | `allow_unverified_effect` where published |
| **Unverified effect** | The native value is proven, but changing it has not been observed in game | `allow_unverified_effect` |
| **Unverified reference** | A reference write (pod slot item) uses the same native mechanism as vanilla, but this replacement has never been spawned there | `allow_unverified_reference` |
| **Shared-object write** | The record is used by more than one weapon, pod or stratagem, and every consumer changes | `allow_shared` |

The gameplay-proven cases in this release are:
- **APW-1 reticle:** third-person reticle off → on (ReticleAmr).
- **Exosuit uses:** the four Exosuits' 3 → unlimited mission uses (Exosuit Unlimited Uses).
- **Mounted-weapon fields:** 27 fields changed by known-working reference mods: the M-103 FRV gun, Emancipator
  and Lumberer arm magazines, and the Patriot's magazines, fire rate, arm health, armor, hit zones and rounds.

## Magazine attachments

Every resolved magazine option is now independently editable, not only a weapon's default magazine.

- **Native decoding.** Each magazine definition's entity delta is decoded against the pinned type library:
  - ammo (`WeaponMagazineComponentData`);
  - reload duration (`WeaponReloadComponentData` +56);
  - `weapon_stat_modifiers` (`WeaponDataComponentData` +956). All 19 `WeaponStatModifierType` names match
    the type library's alias lengths.
- **Resolution.** Catalog options are correlated by every published effect, and narrowed by each weapon's
  own observed unlock list (52 weapons).
  - Resolved options went from 19 to **49**, and ambiguous options from 14 to **0**.
  - Look-alikes are separated: Standard vs Standard Fastreload by reload time; Liberator Drum vs Whisper
    Drum, and the Knight/Gallant and Defender/Pummeler variants, by unlock list.
- **New fields:**
  - `hd2.fields.attachment.reload_duration` (37 definitions, 0.1–20 s);
  - `hd2.fields.attachment.ergonomics_modifier` (24 definitions, −100 to 100). Each write re-proves the
    `Add_Ergonomics` modifier word.
  - Attachment fields went from 172 to **233** across 43 magazine attachments on 23 weapons.
- **Targeting.** `weapon:magazine_attachment(identity)` accepts the catalog name, semantic ID or native name.
  `weapon:magazine_attachments()` returns every resolved option.
- **Metadata.** Each definition publishes `compatibleWeapons` and a full effect list.
  `sdk/WeaponAttachmentCatalog.json` publishes read-only metadata for all 241 customization items: slot,
  patched components, decoded stat modifiers, known consumers and blockers.
- **Still blocked.**
  - The 3 Scythe heatsink options own no magazine.
  - Player preset/selection state is unresolved.
  - `allow_shared` stays required because the consumer set is not proven complete.

See [magazine attachments](../magazine-attachments.md).

## Weapon reticles

New field: **`hd2.fields.weapon.third_person_reticle`** (boolean).

- **Native owner.** `WeaponDataComponent.crosshair_type` (+400, `CrosshairWeaponType`), which is
  weapon-local. Off is `CrosshairDamageIndicatorOnly` (3). On is the weapon's own style, or `AssaultRifle`
  (4) where the baseline hides the reticle.
- **Coverage.** 70 player-weapon and 14 support-weapon fields are writable. Weapons whose value is Default or
  unnamed stay read-only with a reason, and absent reticles are reported as absent.
- **Evidence.**
  - APW-1 Anti-Materiel Rifle 3 → 4 is gameplay-proven (ReticleAmr) and needs no effect acknowledgement.
  - Every other reticle change requires `allow_unverified_effect`.
- **Example.** **ReticleAmrRecreation** matches ReticleAmr's pinned write exactly (+0x190, 3 → 4).

See [weapon reticles](../weapon-reticles.md).

## Fire modes

- **Native model.** Each weapon's own `WeaponDataComponent` record holds:
  - `num_burst_rounds` (+140);
  - four packed `FireMode` slots (+144 to +156). Slot 1 is the default and 0 is empty.
  - `function_info` (+184), which binds the in-game fire-mode selector.
  - FireMode 0–3 (None, Automatic, Single, Burst) match the type library's alias lengths. Values 4–8 are
    charge and safety states; they stay unnamed and are never offered.
  - Fire modes are an enum list, not flags. Rate of fire and burst length are weapon-wide.
- **New fields.** Both are weapon-local and require `allow_unverified_effect`:
  - `hd2.fields.fire_mode.modes`: an ordered list of `'automatic'`, `'single'` and `'burst'`, where the first
    is the default. Up to four modes where a selector is bound; exactly one otherwise.
  - `hd2.fields.fire_mode.burst_rounds`: 1–10.
  - The mode set is written as its four aligned slots in one atomic transaction.
- **Coverage.** 61 writable weapons: 30 player + 3 support selectable, and 19 player + 9 support single-mode.
- **Blocked.** Charge, wind-up, beam, arc, spray and melee weapons; special trigger structures; ambiguous
  identities.
- **Overlap guard.** The older `weapon.default_fire_mode` covers the same bytes, so it can no longer be
  combined with `fire_mode.modes` in one plan.
- **Example.** **JAR5FullAuto** adds Automatic to the JAR-5 Dominator's empty third slot (+152, 0 → 1, one
  4-byte write).
- **Metadata.** `sdk/WeaponFireModeCapabilities.json` is the GUI catalog. `weapon:fire_modes().modeSet` and
  `support_weapon:fire_modes()` describe each weapon.

See [fire modes](../fire-modes.md). **No fire-mode change is live-confirmed.**

## Vehicle mounted weapons

Mounted weapons on vehicles, Exosuits and the GATER rig are reached through the vehicle's mount slot and
edited like support weapons.

- **Coverage.** 11 vehicles, 18 weapon mounts and **480 writable fields**.
- **Weapon-local fields:**
  - fire rate;
  - magazine capacity, starting, from-supply and spare magazines;
  - reload duration (only where the native value is non-zero);
  - the mount's own health and armor;
  - the Exosuit arms' single hit-zone health and armor.
- **Shared fields.** Projectile, damage, explosion and explosion-damage settings rows, each listing its other
  consumers.
- **Ownership scopes:**
  - `weapon_local`: 106 fields.
  - `shared_mounted_weapon`: 26 fields. One gun entity sits in several mounts (both FRV variants' gun;
    Maelstrom slots 3 and 4).
  - Shared settings: 348 fields.
  - Every shared scope requires `allow_shared`.
- **Separate weapons.** Each mount is its own weapon. The Maelstrom's main gun, missile pod and twin launchers
  are separate, and so are the two arms of each Exosuit.
- **Mount re-check.** Every write re-reads the vehicle's `MountComponentData` and refuses if the slot no
  longer holds the reviewed weapon.
- **Evidence.** 27 fields are gameplay-proven by reference mods. The other **453 require
  `allow_unverified_effect`**.
- **Read-only.** The damage/armor-penetration addends (the type library and a reference mod disagree), and
  the Health "max armor" values.
- **API.** `vehicle:weapons()`, `vehicle:weapon(slot | label | key | semanticId)`, `mount:weapon()`,
  `weapon:projectile()`, `weapon:explosion()` and `weapon:attack(role)`.
- **Examples.** Five reference-mod recreations match exactly, with omissions listed:
  - **EmancipatorAmmo**;
  - **LumbererAmmo**;
  - **M103TurretMagazine** (magazine only; addends omitted);
  - **PatriotExosuitBuffs** (all but the max-armor values);
  - **ExosuitUnlimitedUses**, listed under mission uses below.
- **Research.** `research/reference-mod-inventory-F5FEE03DCFDB.json` pins all seven reference ZIPs.

See [vehicle weapons](../vehicle-weapons.md).

## Stratagem mission uses

**`hd2.fields.stratagem.max_uses` is now writable** for every non-Eagle stratagem.

- **Native value.** `StratagemInfo` +80 (u32). The game's own unlimited value is `0xFFFFFFFF`; the runtime
  writes exactly that for `'unlimited'` and never substitutes a large count.
- **Transitions.** Finite → unlimited, unlimited → finite, and finite → a different finite count (1–100).
- **Coverage.** **85 stratagems:** 80 unlimited by default, plus 5 finite (the four Exosuits and the Orbital
  Laser, at 3).
- **Eagles.** They stay read-only here, because the same field means uses per rearm on Eagles. That is
  already editable as `eagle.uses_per_rearm`.
- **Evidence.**
  - The Exosuit 3 → unlimited change is gameplay-proven (Exosuit Unlimited Uses) and needs no effect
    acknowledgement.
  - Every other change requires `allow_unverified_effect`.
- **Caveat.** The mission host applies use counts, and the HUD may keep showing the old count until the next
  mission.
- **Example.** **ExosuitUnlimitedUses** matches the reference mod exactly (4 × 3 → `0xFFFFFFFF`).

See [stratagem uses](../stratagem-uses.md).

## Backpack-fed ammo

The M-1000 Maxigun, B/FLAM-80 Cremator and GL-28 Belt-Fed Grenade Launcher own **no weapon magazine**.
Their ammunition is their backpack's `DepositComponent`.

- **Native chain:**
  1. The call-in rack delivers the weapon and the backpack.
  2. The weapon's `WeaponLinkedAmmoComponent` draws from the Backpack inventory slot through a tag.
  3. Only that weapon's backpack carries the tag.
  4. That backpack's deposit holds `capacity` (+0), `start_amount` (+4) and `refill_amount` (+8).
- **Fingerprints.** Scraped capacity and supply values match exactly:

  | Weapon | Capacity | From supply |
  | --- | --- | --- |
  | Maxigun | 1000 | 500 |
  | Cremator | 500 | 250 |
  | GL-28 | 120 | 60 |

  The ammo-box refill is half the supply refill; game code applies it, so it is not authorable.
- **API.**
  - `hd2.support_weapon(name):backpack()`, and the reverse `backpack:weapon()`.
  - `hd2.fields.deposit.capacity`, `start_amount` and `refill_amount` are writable on the three weapon-fed
    backpacks, and require `allow_unverified_effect`.
  - Every write re-proves the rack, the tag and the linked-ammo slot.
- **Unchanged.**
  - Call-in backpack deposits (Supply Pack, drones, Hellbomb) stay read-only.
  - Team-reload backpacks (recoilless, autocannon, Spear, airburst, C4) use a different mechanism and stay
    read-only.
- **Correction.** The 0.24.0 note that the Cremator's scraped 500 matched an Exosuit root is superseded: it
  is the backpack deposit. The Cremator's weapon-side fields remain blocked (duplicate roots).
- **Example.** **MaxigunBackpackAmmo** doubles capacity, start amount and supply refill.

See [backpack ammunition](../backpack-ammo.md).

## Drop-pod payload authoring

Mods can change what a hellpod opens with, and how many items spawn.

- **Native model:**
  - A call-in's primary payload is a hellpod rack.
  - Its `HellpodRackComponent` holds 8 `RackAttach` slots (64 bytes each): item entity reference, attach
    node, rack side and `apply_deltas`.
  - The first `spawn_payload_size` slots spawn. The same item may fill several slots, and an active slot may
    be empty (the EAT-411 Leveller does this in vanilla).
- **Shared racks.** The rack is the semantic owner, and one rack can serve several stratagems.
  - **The Surplus EAT Allocation pod is the EAT-17 call-in's pod.** Both use `weapon_rack_lat_oneshot`, so an
    edit changes both.
  - Six shared racks require `allow_shared`.
- **Coverage.** 48 of 56 rack pods are writable: slots 1–4 (**192 slots**) plus a spawn count (1–4) each.
- **Read-only racks:**
  - Solo Silo, Remote Explosives, Carry Data, Cyborg Carry Data and Spire Sterilizer deliver deployables or
    objectives.
  - TX-41 Sterilizer and Dark Fluid Backpack have items with no resolvable name.
  - The Jammed Pod picks at random.
  - Slots 5–8 are read-only.
- **Pickup catalog (68).** Categories are typed from the native pickup interaction or backpack component:
  37 support weapons, 25 backpacks, 2 ammo, 2 stims, 1 grenade box and 1 supply box.
  - 60 are rack-proven (`SCHEMA_COMPATIBLE`) and 8 are standalone pickups (`UNVERIFIED_REFERENCE`).
  - World-loot evidence comes from the loaded `LevelGenerationSettings` cache (bunker) loot tables. It covers
    14 pickups and is published separately from pod compatibility.
- **Package risk.** Published separately from compatibility.
  - Only the Supply Box is always resident, because Resupply is available in every mission.
  - Other replacements depend on their own package being loaded when the pod spawns.
- **API.**
  - `hd2.stratagem(name):delivery():rack()` / `:payload()`;
  - `hd2.booster(name):granted_stratagem():delivery():rack()`;
  - `hd2.pod_rack(name)`, `rack:slot(n)` and `slot:current()`;
  - `hd2.pickup(name)` and `hd2.pickups(category)`;
  - `hd2.fields.payload.entity` (a pickup or `'empty'`; raw IDs are rejected) and
    `hd2.fields.payload.spawn_count`.
- **Acknowledgements.**
  - `allow_unverified_reference` for any non-vanilla item;
  - `allow_unverified_effect` for spawn counts;
  - `allow_shared` for shared racks.
- **Re-proof.** Every write re-proves:
  - each consumer stratagem's payload;
  - the rack's ownership and non-random mode;
  - the slot's attach node;
  - the current reference;
  - the replacement's pickup component.
- **Example.** **SurplusEatPodSwap** is a live test: two Supply Boxes instead of two EATs.

See [pod payloads](../pod-payloads.md).

## Validation

- **Snapshot overlays.** Each field gets an unchanged-value no-op (or baseline check), changed write,
  read-back, rollback, conflict rejection and acknowledgement rejection:

  | Area | Coverage |
  | --- | --- |
  | Magazine attachments | 233 fields, plus isolation and range |
  | Reticles | 84 |
  | Fire modes | 61 weapons × 2 fields |
  | Vehicle weapons | 480, plus mount-chain rejection for 18 weapons |
  | Stratagem uses | 85 |
  | Backpack ammo | 9, plus 12 chain-tamper rejections |
  | Pod payloads | 192 slots and 48 spawn counts, plus 8 rejection and tamper cases |

- **Reference recreations.** 11 of 11 are exact byte matches, 5 of them new in this release.
- **Packaged runtime.** **36 scenarios**, up from 20 in 0.25.1, run from the built runtime ZIP with late
  module lookups disabled. Every ensure applies, verifies and re-applies after a simulated game reset. The
  new scenarios are:
  - `magazine-attachment-options`, `support-weapon-reticle` and `player-weapon-reticle`;
  - `fire-mode-jar5-full-auto` and `fire-mode-burst-and-automatic`;
  - `vehicle-weapon-frv`, `-tank`, `-emancipator`, `-lumberer` and `-patriot`;
  - `stratagem-uses-unlimited` and `stratagem-uses-finite`;
  - `backpack-ammo-maxigun` and `backpack-ammo-coverage`;
  - `pod-payload-surplus-eat` and `pod-payload-coverage`.
- **Build checks.** The full unit suite passes, and every generator checks as current at build time.

## Known limitations / live-test caveats

- **Not live-tested:**
  - **Backpack ammo:** no edit has been confirmed in game.
  - **Pod payloads:** no slot swap or spawn-count change has been confirmed in game. SurplusEatPodSwap is
    the intended first live test.
- **Package risk.** Every pod replacement other than the Supply Box may reference assets that are not loaded
  when the pod spawns.
- **Shared EAT pod.** Editing the Surplus EAT pod also changes the ordinary EAT-17 pod (`allow_shared`).
- **Unverified mounted-weapon fields.** 453 of 480 fields require `allow_unverified_effect`, and the addends
  stay read-only pending one in-game test.
- **Fire modes.** No fire-mode change (including JAR-5 full-auto) is live-confirmed.
- **Reticles.** Reticle changes other than the APW-1 are not live-confirmed.
- **Stratagem uses.**
  - Only Exosuit 3 → unlimited is gameplay-proven.
  - Use counts are host-applied, and the HUD may lag until the next mission.
- **Magazine attachments.** Consumer sets are not proven complete (`allow_shared`). Scythe heatsinks and
  player preset selection remain blocked.
- **Not exposed.** Tanks Overhaul's zone explosion multipliers, linked-zone fractions and vehicle physics;
  Health max-armor values.
