# HD2Runtime 0.23.0

HD2Runtime 0.23.0 adds guarded authoring for vehicles, vehicle weapon mounts, backpacks, and the
Shield Generator Relay's shield. Every promoted field is resolved through typed native ownership, has
an exact baseline, and was validated as a guarded no-op against the retained current-build snapshot.

- **Vehicles** (`hd2.vehicle`, `sdk/VehicleAuthoringCapabilities.json`): 9 wiki vehicle stratagems
  plus the Super Earth FRV and GATER oil rig. Main health, main armor, and 226 populated damage zones
  (zone armor, zone health, damage forwarded to main health) use the shared `HealthComponent` schema.
- **Mounts:** 18 swappable mount slots. Their replacements come from 79 discovered mounted weapons in
  163 native mount records, limited to the same attack family and gated by
  `allow_unverified_reference`.
- **Backpacks** (`hd2.backpack`, `sdk/BackpackAuthoringCapabilities.json`): 13 backpacks resolved
  through their hellpod racks. Jump Pack recharge and launch velocity, Hover Pack recharge, Shield
  Generator Pack shield, and shield-backpack health are writable. Deposit charges are read-only.
- **Shield Generator Relay:** shield radius and health as a separate `shield` target, deployed
  lifetime, and damage zones for all deployed entities.
- **Stratagem catalog:** 22 new vehicle and backpack call-in definitions with writable cooldowns and
  bidirectional delivery links.

Each field publishes an evidence tier: `gameplay_proven`, `gameplay_proven_combined`,
`schema_proven`, `live_write_verified`, or `structural_reference`.

Four example projects recreate the reference mods through the public API only: `ShieldRelayRecreation`,
`BastionReArmoredRecreation`, `FRVWeaponSwapRecreation`, and `JumpPackRecreation`. The script
`scripts/validate_reference_recreations.py` resolves each plan against the snapshot. It confirms that
the physical write set matches each mod's pinned native edits exactly: 68 writes in total.

Fixes:

- `hd2.support_weapon` (and the new `hd2.backpack`) is now exported from the public module.
- The stratagem snapshot validator carries full deployed-entity target identity; its results now cover
  all 1368 checked instances.

Runtime cost audit (see [runtime performance](../runtime-performance.md)):

- Steady state is near idle. After an ensured mod applies, only its target bytes are re-checked, at an
  interval that backs off from 60 s to 600 s. Previously every 60 s re-ran discovery, catalog building,
  the transaction guard, logging, and 2 to 8 synchronous ~15 MB module hashes (~9 ms each) per mod.
  That was a periodic frame hitch.
- The build fingerprint is hashed once per process and shared by all mods.
- Guarded operations are serialized process-wide, so mods starting together no longer reject each other.
- Discovery results are reused, after re-validation, for back-to-back operations. Entity catalog
  capture no longer builds membership sets for every entity. The update hook no longer allocates a
  table every frame.
- `hd2.metrics()` exposes work counters, and `hd2.ensure` accepts `max_interval`.

Fixes found by the audit:

- Typed StratagemDefinition writes (cooldowns, Eagle uses and rearm) were captured twice and refused
  by the transaction core at apply time. They now apply.
- 8-byte mount-reference writes were refused by the transaction core and the native writer. Mount
  swaps now apply.
- Guarded operations now retry transient not-ready failures up to 6 attempts, 5 s apart; this also
  applies to ensure reapplication. Previously the write path rejected on its first
  `TARGET_UNAVAILABLE`, and ensure made that terminal. Deterministic failures still fail on the first
  attempt. A not-yet-initialized stratagem table now reports `TARGET_UNAVAILABLE` instead of an
  extent assertion.

Magazine attachments:

- Magazine attachment definitions (`hd2.weapon_attachment`, `weapon:magazine_attachments()`) expose
  capacity, starting magazines, magazines from supply, and spare magazines for 43 native attachments.
- Their owner is the entity delta keyed by each attachment's AddPath. The weapon record's own
  capacity is a placeholder on 14 attachment weapons.
- Writes require `allow_shared` and `allow_unverified_effect`.
- Magazine selection remains read-only.
