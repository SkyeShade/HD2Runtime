# HD2Runtime 0.25.0

HD2Runtime 0.25.0 traces Booster implementation natively, resolves the last support-equipment
call-in relationships, and adds in-game options bound to ensured operations.

## Boosters

The research reads the unpacked `game.dll` image from the retained snapshot and traces each
booster through the code that implements it. All 20 boosters now resolve to a unique identity,
and **19 of 20 are writable** (was 2), with **42 field instances** (was 5). All writes go
through data only; no executable code is written.

| Target | What it writes | Acknowledgement |
| --- | --- | --- |
| `booster:tuning()` | 13 native booster-table scalars (Vitality 0.9, Stamina 1.3, Muscle 0.35, UAV 1.5, …), range-checked | `allow_unverified_effect` |
| `booster:explosion()` | Firebomb, Stun and smoke hellpod-impact explosions | `allow_unverified_effect`, `allow_shared` |
| `booster:status_damage()` | Dead Sprint status damage | `allow_unverified_effect`, `allow_shared` |
| `booster:granted_stratagem()` | Surplus EAT uses | `allow_unverified_effect` |

Every write re-proves the live build, module layout, the Booster enum-name table, table row
identities and the exact bytes of each pinned gate. Hellpod Space Optimization stays blocked,
because it has no scalar to tune. Examples: `BoosterTuning`, `IncendiaryHellpods`.

## Support equipment

B/MD C4 Pack now links to its call-in through two native loadout identities. SG-88
Break-Action Shotgun and CQC-72 Entrenchment Tool are recorded as `no_call_in` (world pickups)
rather than unresolved. Write guards are unchanged.

## In-game options

`hd2.options({id, title})` declares sliders, choices and toggles on the MODS tab added by
CowboyBingus **Mod Options Menu** v1+ (api 1). Its handles bind a field `value`, or `enabled`,
in `hd2.ensure`. APPLY re-resolves the same guarded operation, and disabling restores the
reviewed baseline. See [options](../options.md) and the `LiberatorDamageOptions` example.

Mod Options Menu, which needs Bingus Shared Loader v18+, is an **optional** dependency of
mods that call `hd2.options`. HD2Runtime still needs only Bingus Shared Loader v15+ / API 1.
Without the menu, option-bound operations stay inactive for the session with one warning.
Declare the dependency in `hd2runtime.json`:

```json
"optional": {"mod_options_menu": {"min_version": "1.0.0", "api": 1, "bingus_min_release": 18}}
```

Not yet confirmed in game: rows on the MODS tab, APPLY driving the binding, and saved values.
These are validated offline against Mod Options Menu's own source and the retained snapshot.

## Compatibility

Pinned to the same build as 0.24.0: `HELLDIVERS 2` exe `F5FEE03DCFDB…`, Steam build 25480438.
Mods that do not use the new APIs may keep a lower `min_version` (never below 0.23.2).
