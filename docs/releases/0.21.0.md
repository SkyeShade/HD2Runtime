# HD2Runtime 0.21.0 stratagem authoring report

The retained current-build snapshot resolves all 20 imported offensive stratagem roots: 12
Orbital and 8 Eagle. It also resolves 33 of 35 support-weapon call-in definitions independently
of support-weapon runtime identity. SG-88 Break-Action Shotgun and CQC-72 Entrenchment Tool stay
blocked because no unique call-in definition was correlated.

Cooldown is writable on all 53 resolved roots. The Shield Relay gameplay proof anchors the
shared StratagemInfo layout and each promoted root additionally checks its current identity,
package, complete payload list, group, row, exact baseline, and stable reread. Solo Silo now has
a separately owned 180-second call-in cooldown; its existing missile and two-explosion graph is
unchanged.

Eagle `uses_per_rearm` is the per-stratagem static definition value. Current baselines are 2 for
Gas, Airstrike, Smoke, and Napalm; 4 for Strafing and Cluster; 3 for Rocket Pods; and 1 for the
500kg Bomb. `eagle.rearm_time` belongs to a separate shared Eagle rearm definition with a
150-second baseline and an exact consumer scope of all eight Eagle offensive stratagems. Ship
module transformations are downstream behavior and are not represented as changes to these
base definitions. Live remaining-use and rearm counters are not written.

The offensive graph preserves all 55 imported descriptive branches (22 projectile, 22
explosion/AoE, 10 status, and one beam-classified branch) alongside 143 native backing-object
branch instances: 33 ProjectileSettings, 64 DamageInfo, 32 ExplosionSettings, 13
StatusEffectSettings, and one Orbital Laser ability/beam object. Repeated delivery slots stay
separate semantic instances even when they share one native settings object. The catalog has 989
field instances, of which 936 are writable, across 135 opaque backing-object groups and 81
reviewed shared scopes.

Orbital Laser reproduces the prior gameplay-proven 60-to-400 standard-damage mutation through
`hd2.stratagem("Orbital Laser"):attack("beam_damage")`. Its duration, movement speed, search
radius, and 0.1-second tick interval are separately owned OrbitalAbility scalars. Projectile,
DamageInfo, ExplosionSettings, explosion DamageInfo, and status fields reuse the existing
`hd2.fields.*` semantics.

Bombardment delivery is an inline typed projectile-reference array. Some barrages contain
multiple slots and repeated references. The array proves delivery structure but does not prove
scalar shell count, volley count, shells per volley, shell interval, volley interval, duration,
or barrage radius semantics. Those proposed barrage fields were therefore not added. Static
maximum-use values and the unlimited sentinel are published read-only; mutation remains blocked
pending gameplay proof. The structurally visible spawn-time scalar does not reproduce wiki
call-in time across families and is also blocked.

The canonical GUI contract is `sdk/StratagemAuthoringCapabilities.json` schema 1. It is
per-instance from its first release and contains exact baselines, semantic paths, opaque backing
object IDs, shared consumers, operation groups, plan groups, dependencies, units, field
constants, provenance, and blocked reasons. It contains no addresses, native offsets, record
indices, or native resource identifiers.

Snapshot validation resolved 210 writable semantic objects and 929 distinct field instances
(the shared Eagle rearm object is validated once rather than eight times). It reports
`researchWrites=0`, `protectionChanges=0`, and `fixtureFallback=disabled`. The opt-in packages
`OrbitalLaserProof`, `OrbitalPrecisionProof`, `OrbitalBarrageProof`, `EagleProof`, and
`SupportStratagemCooldownProof` were built but were not deployed or launched.
