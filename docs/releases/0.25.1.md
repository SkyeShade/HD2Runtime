# HD2Runtime 0.25.1

HD2Runtime 0.25.1 is a follow-up to 0.25.0. It makes two changes:

- It publishes the stratagem icon identity metadata that 0.25.0 omitted.
- Mod Options Menu becomes a true enhancement: without it, option-bound operations run with
  their declared defaults.

Guards, acknowledgements, reviewed ranges and baselines are unchanged.

## Why

- **Icon metadata.** The stratagem icon identity work was developed on a separate branch from
  0.24.0 and was not merged before 0.25.0 was built. As a result, **0.25.0's
  `StratagemAuthoringCapabilities.json` has no stratagem icon identity metadata**. 0.25.1 adds it.
- **Options fallback.** In 0.25.0, a mod whose operations were bound to options did nothing
  unless the player had installed Mod Options Menu. That made an optional menu effectively
  required for the mod to work.

## Stratagem icon identity

Each stratagem in `sdk/StratagemAuthoringCapabilities.json` now has a `uiIcon` entry. The file also
has a top-level `uiIconContract` (contract `hd2runtime.stratagem.ui_icon.v1`). See
[stratagem authoring](../stratagem-authoring.md).

- **`iconKey`** names the game's own icon template for the stratagem, found through a
  structural chain. Display names are never used:
  1. `StratagemInfo.type`;
  2. the `game.dll` StratagemType name table (all 151 entry lengths match the type library);
  3. the UI's `StratagemTypeDataTemplate` binding;
  4. the `DataTemplate` in the icon library.
- **`state`** is one of `resolved`, `empty_template`, `unbound` or `no_native_root`. For any state
  other than `resolved`, `blocker` gives `{kind, reason}`.
- **`provenance`** records the evidence behind the mapping. It is `null` when there is no native
  root.
- **`uiIconContract`** documents the states and the chain, the icon library resource, and its
  pinned SHA-256.

| --- | ---: | --- |
| `resolved` (known icon key, vector artwork) | 84 | |
| `empty_template` (key bound, template empty in this build) | 4 | M-1000 Maxigun, LIFT-850 Jump Pack, AX/LAS-5 Rover, AX/FLAM-75 Hot Dog |

No two stratagems resolve to the same template.

**No artwork is published.** The runtime and SDK ship only identity and key metadata
(`artworkPublished: false`). Tooling reads the icons read-only from the player's installed game
and checks `librarySha256` against the reviewed build.

**GUI builds that already support icon keys will show the real game icons automatically.** They
import the icons from the local installation, and no GUI change is needed. Stratagems in the
non-`resolved` states keep their fallback.

### Catalog equipment associations

The same branch adds `catalogEquipment` to each of the 35 support stratagems. It pairs the call-in
with the equipment of the catalog record it was generated from. It is for presentation only:
`delivers` and `linkedStratagem` remain the only ownership links. With 0.25.0's native C4 link,
only CQC-72 Entrenchment Tool and SG-88 Break-Action Shotgun are catalog-only
(`summary.catalogOnlyEquipment`).

## Mod Options Menu fallback

`hd2.options` pages take a new `fallback` setting. See [in-game options](../options.md).

| Situation | `fallback='default'` (the default) | `fallback='disable'` (strict) |
| --- | --- | --- |
| Menu installed | Saved and live values, as in 0.25.0 | Same |
| Menu missing, incompatible, or rejecting an option | One warning; bound operations **run with the declared defaults** | One warning; bound operations stay inactive for the session (the 0.25.0 behavior) |

```
[HD2Runtime] options liberator_damage unavailable: Mod Options Menu is not installed; using configured defaults
```

```lua
local options=hd2.options({id='liberator_damage',title='Liberator Damage'})                  -- defaults
local strict=hd2.options({id='liberator_strict',title='Liberator Strict',fallback='disable'})  -- strict
```

- **Defaults are not a bypass.** Every declared default is validated with the operation when the
  `hd2.ensure` is declared, together with the rest of the option's domain, in both modes. A
  default outside a field's reviewed range, or one that would need a missing `allow_shared`,
  `allow_unverified_effect` or `allow_unverified_reference`, fails at startup. `expect` stays the
  reviewed baseline; transactions and plans stay atomic.
- **The decision is made once.** Availability is decided once per session: at once when a menu is
  present, otherwise after the 5-second startup grace period. The menu is never probed again,
  the warning is not repeated, and nothing is retried. Once applied, a default-driven operation
  is an ordinary ensure: its steady state is the same byte check with the same back-off.
- **Unavailable options always use their declared default**, even if the menu returned a saved
  value before it failed. Other options on the page stay live.
- **Unrelated operations are unaffected** in both modes.
- **Introspection.** `:describe().fallback`, `Page:describe().fallback` and the ensure watch's
  `option_defaults` flag report the mode. The manager-description note now reads "without it the
  settings use their defaults".
- **Tools that generate mods should use the default mode.**

The live confirmation in [0.25.0](0.25.0.md) was made with the 0.25.0 behavior, which is now
strict mode. The default mode is validated offline and from the built runtime ZIP.

## Validation

- The packaged-runtime validator applies **20 scenarios** from the built runtime ZIP (0.25.0: 19):
  - `options-missing` now checks that the default is applied once, with one warning and no retries;
  - the new `options-missing-strict` checks the strict mode;
  - `options-test-mod-missing` runs the in-game test mod with its default of 100.
- Unit tests cover:
  - the menu present;
  - the menu missing, in the default mode and in strict mode;
  - incompatible, rejecting and duplicate registrations in both modes;
  - invalid defaults and acknowledgements at declaration;
  - unrelated operations;
  - no re-probing and no repeated warnings.

## Compatibility

- **Mods that call `hd2.options` should require 0.25.1.** On 0.25.0, a `fallback` key is rejected,
  and without the menu bound operations stay inactive. `LiberatorDamageOptions` and the
  `HD2RuntimeOptionsTest` live-validation mod now require 0.25.1.
- Mods that do not use options may keep `min_version` 0.25.0. The ModTemplate still requires
  0.25.0, and its README says to raise it when adding options.
- No runtime write targets or fields changed. Booster native coverage (19 of 20 writable, 42
  fields, all 20 uniquely identified) and the support call-in links are as in 0.25.0.
- Pinned to the same build: exe `F5FEE03DCFDB…`, `game.dll` `2E2C3B7C…`, Steam build 25480438.
