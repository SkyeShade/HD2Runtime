# Live evidence

Generated by `scripts/generate_live_evidence.py` from `schemas/live_evidence.json`, the one place in-game test results are recorded. The public copy is `sdk/LiveEvidenceCatalog.json`.

A capability family is **live-proven** only when a user-run in-game test showed the intended effect. Only live-proven families drop `allow_unverified_effect`, and only within the scope below. Their fields carry a `liveEvidence` reference in their own capability catalogs. Tests that were not run or were inconclusive leave the family offline-proven.

## Notes

**`sentry_turret_turn_speed`**
- Not promoted (still need `allow_unverified_effect`): turret.pitch_min, turret.pitch_max, turret.yaw_min, turret.yaw_max.

**`minefield_salvos`**
- Behaviour: Salvos are sequential launcher sweeps over different rotational sectors; reducing the count truncates the angular deployment (fewer sectors covered), it does not thin mines evenly around 360 degrees.
- Not promoted (still need `allow_unverified_effect`): minefield.mines_per_salvo.

**`weapon_projectile_status_reference`**
- Observation: Stun Medium held targets about 1-2 s instead of the catalogued 3 s; cause not established.
- Not promoted (still need `allow_unverified_effect`): status slots on explosion, spray, beam, arc and melee DamageInfo rows, status slots on vehicle mounted weapons.

**`structure_health`**
- Analysis: Offline data offers one explanation, not established: the fabricator's fatal 'insides' zone has its own 400-health pool and forwards 0% of its damage to main health, so a fabricator destroyed through that zone needs the same shots whether or not main health changed.
- Next tests: `FabricatorHealthAllVariants`, `GazerHealthTest`.
